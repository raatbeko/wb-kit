Посчитай продавцу план закупки. Аргументы: $ARGUMENTS

## 1. Собрать

- «демо» или «demo» в аргументах, либо ключа WB нет → `npm run plan -- --demo`. Скажи, что магазин выдуманный.
- Иначе — `npm run plan` (таймаут 10 минут). Предупреди: «Это займёт около 5 минут — WB отдаёт историю продаж за год по 3 запроса в минуту».
- Параметры из слов человека:
  - «на 4 месяца» → `--months 4` (от 1 до 6, по умолчанию 3);
  - «везём 30 дней», «производство месяц» → `--lead 30` (срок от заказа поставщику до приёмки на складе WB, по умолчанию 21);
  - «запас 20%» → `--safety 20` (по умолчанию 15).
- Срок поставки по умолчанию — 21 день. Если человек его не называл — спроси одной строкой после отчёта: от срока зависит «заказать до».
- Нужно быстро и без сезона — `--no-season`: 1 запрос вместо 13, прогноз только по последним 4 неделям.

Живой статус для панели — как в `.claude/commands/panel.md`: перед сбором `run` «План закупки», `step` «Собираю продажи за год — около 5 минут»; в конце `done: true`.

## 2. Выводы

Прочитай `summary.json` в папке `reports/plan-ГГГГ-ММ-ДД[-demo]` и напиши там же `insights.md`:

- **Заказать сегодня** — товары из `urgent`: сколько штук и почему срочно (остатка меньше, чем срок поставки).
- **Локомотивы** — товары с `locomotive: true`: на них держится предмет, их заказывают первыми и с запасом.
- **Сезон** — какие предметы сезонные (`seasonalSubjects`), что будет с продажами в месяцах плана.
- **Лишний остаток** (`overstock`) — что не заказывать и что сделать с остатком (акция, вывоз).
- **Деньги** — сколько нужно на закупку (`totals.money`). Нет себестоимости — так и скажи и предложи `npm run cost -- --init`.

Правила: только цифры из выжимки, простыми словами, прогноз называй прогнозом. Затем `npm run plan -- --render <папка>` (те же `--months`/`--lead`/`--safety`, что при сборе).

## 3. Ответить

Коротко: сколько и чего заказать в первую очередь, общая сумма, путь к HTML (там фото товаров) и Excel — его можно поправить и отправить поставщику. Панель обновится сама, вкладка «Закупка».

Цифры в кабинете WB этот план не меняет. Остатки FBS (`update_fbs_stocks`) — только по отдельной просьбе, с таблицей «было → станет» и после «да».
