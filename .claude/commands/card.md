Помоги продавцу улучшить текст карточки товара. Аргументы: $ARGUMENTS

Если в аргументах «демо» или «demo» — выполни `npm run card -- --demo` и переходи к шагу 3 (папка `reports/card-MUG-CERAMIC-400-ГГГГ-ММ-ДД-demo`). Скажи, что это выдуманная кружка.

## 1. Какой товар

- Артикул из аргументов — как есть (артикул WB или артикул продавца).
- Если аргумента нет — спроси, какой товар. Можно подсказать: товары из последнего аудита (`reports/audit-*/summary.json`) с проблемами карточки или низкой конверсией в корзину.

## 2. Собрать данные

`npm run card -- <артикул>` (таймаут 5 минут). Скрипт возьмёт:
- карточку из кабинета (название, описание, характеристики, фото);
- поисковые запросы покупателей по этому товару за 30 дней — из аналитики WB;
- карточки конкурентов из последней проверки `/competitors` по главному запросу товара.

Если скрипт написал, что конкурентов нет, предложи одно из двух:
- снять выдачу по главному запросу — шаги 1–3 команды `/competitors` для одного запроса (это 3–5 минут), потом снова `npm run card -- <артикул>`;
- или человек сам называет 5–10 конкурентов: `npm run card -- <артикул> --competitors 123,456` (можно ссылками на товары).
Можно и без конкурентов — тогда сравнение только с запросами.

Если поисковых запросов нет (в выводе и в `summary.json` → `searchTextsError`) — объясни причину простыми словами. Без них текст всё равно можно улучшить по конкурентам, но скажи, что это менее точно.

## 3. Написать предложение

Прочитай `summary.json` в папке отчёта и запиши туда же `proposal.md` строго с такими разделами (заголовки — ровно эти, второго уровня):

```markdown
Коротко: 2–3 предложения — что не так сейчас и что даст правка, с цифрами из summary.json.

## Название
Одна строка.

## Описание
Текст описания.

## Характеристики
- Название поля: значение

## Уточнить у вас
- вопрос продавцу

## Фото и инфографика
Бриф: что снять и какие слайды сделать.
```

Правила текста:
- **Только правда про этот товар.** Слова из `missingWords` и `competitorWords` — кандидаты, а не обязанность. Если слово может быть неправдой («с крышкой», «ручной работы», «в микроволновку») — не вставляй, а спроси в «Уточнить у вас». Неправда в карточке — это возвраты и плохие отзывы.
- **Название** — не длиннее `limits.title` (60) символов. Сначала тип товара и самые частые слова из запросов (`topQueries`, `notInTitle`), потом важные свойства (размер, объём, материал). Пиши для человека: без капса, без повторов, без списка слов через запятую. Бренд не повторяй — WB показывает его рядом с названием.
- **Описание** — 1000–2000 символов обычного текста без разметки и эмодзи, абзацами. Отвечай на вопросы покупателя: что это, размер и объём, материал, уход, комплектация, для кого и для чего. Слова из частых запросов — естественно, 1–2 раза, не списком. Без ссылок, телефонов, названий других магазинов и брендов, без «лучший», «№1».
- **Характеристики** — только поля, которые явно подходят товару и которых нет или они заполнены не полностью. Размеры и свойства, которых ты не знаешь, не придумывай — спроси.
- **Фото и инфографика** — сравни с конкурентами (`competitors.photosMedian`, `withVideo`): сколько и каких кадров добавить, что вынести на инфографику (главные свойства из запросов и вопросы покупателей).
- В «Коротко» — только цифры из `summary.json`.

Потом `npm run card -- --render <папка отчёта>`. Если скрипт вывел ⚠ (название длиннее 60, нет раздела) — исправь `proposal.md` и пересобери. Скрипт посчитает, какая доля спроса покрыта сейчас и станет покрыта после правки.

## 4. Ответить

- Новое название и почему оно такое (одна строка «было → стало» и доля спроса «было → станет» из вывода скрипта).
- Вопросы из «Уточнить у вас» — задай их прямо; после ответов поправь `proposal.md` и пересобери отчёт.
- Где отчёт: HTML (откройте двойным щелчком) и Excel в `reports/card-…`.
- Как применить: кабинет WB → Товары → Карточки товаров → карточка → Редактировать, вставить название, описание, заполнить характеристики (значения выбираются из справочника WB). wb-kit карточки сам не меняет — так задумано.
- Через 1–2 недели стоит повторить `/card <артикул>`: в таблице запросов будет видно, как изменились позиции и переходы.

## 5. Инфографика через MPSTATS (только если подключён)

Посмотри, есть ли среди твоих инструментов MCP-сервер MPSTATS (`mcp__mpstats__*`) с генерацией фото или инфографики.

- Нет — скажи, что бриф из раздела «Фото и инфографика» можно отдать дизайнеру или фотографу.
- Есть — предложи: «Могу сделать слайды инфографики по этому брифу через MPSTATS. Это расходует лимиты вашей подписки MPSTATS. Сделать?» Без явного «да» не запускай.
- После «да» исследование уже сделано здесь (запросы, конкуренты, бриф) — переходи к генерации. Сначала один пробный кадр, покажи его и спроси, делать ли остальные. Готовые файлы сохрани в `<папка отчёта>/фото/` с понятными именами (`слайд-1-главный.png`).
- Загружать фото в карточку WB — тоже вручную, через кабинет.
